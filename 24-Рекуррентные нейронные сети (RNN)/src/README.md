# Локальный учебный пример RNN

Все данные создаются на месте. Сеть и BPTT реализованы на NumPy, без PyTorch,
скачивания датасетов, сетевых запросов и публикации результатов.

## Быстрый запуск

Из каталога темы:

```sh
python3 src/run_demo.py
python3 src/numerical_example.py
```

Нужен Python 3.11+ и NumPy; фактический запуск выполнен с NumPy 2.3.5.
Ноутбук `demo.ipynb` содержит объяснения, запускаемые ячейки и сохранённые
выводы настоящего выполнения. Его можно читать без повторного обучения.
Для интерактивного запуска нужен обычный Jupyter-совместимый редактор.

## Что именно проверяем

Модель различает возрастающие и убывающие последовательности длины 12.
Для каждой возрастающей последовательности создаётся обратная: набор значений
и среднее совпадают, а метки противоположны. Все значения вещественные;
у разных пар разные смещения и масштабы. Сначала случайно разделяются ID пар,
затем оба направления каждой пары попадают в один split. Это исключает
попадание прямой последовательности в train, а её обратной — в test.
Стандартизация рассчитывается только по train.

Архитектура: один скалярный вход → 8 скрытых компонент с `tanh` → последний
скрытый вектор → один logit → `sigmoid`. Всего 89 обучаемых параметров.
Обучение: BCE, полный BPTT по 12 шагам, Adam с lr=0.01, batch=64,
150 эпох, ограничение общей нормы градиента до 1. Seeds: данные 24,
инициализация 25, перемешивание батчей 26. Test используется один раз после
обучения; отдельного подбора настроек по test нет.

## Фактический результат

| Метрика | Train | Test |
|---|---:|---:|
| Число исходных пар | 256 | 128 |
| Число последовательностей | 512 | 256 |
| Accuracy RNN | 100% | 100% |
| BCE RNN | 0.0009645370 | 0.0014192692 |
| Правило «среднее ≥ 0» | 50% | 50% |
| Правило «последний > первый» | 100% | 100% |

Ожидаемая accuracy случайного угадывания — 50%. Постоянный ответ одного
класса также даёт ровно 50%, так как классы сбалансированы.

Почему среднее бессильно: любой детерминированный классификатор только по
среднему предсказывает один класс обоим членам пары. Их метки противоположны,
поэтому он правильно отвечает ровно для одного из двух. В реализации среднее
считается после сортировки, чтобы одинаковый набор значений суммировался
в одинаковом порядке и ошибки округления не создавали ложных отличий.

Это демонстрация механики RNN, а не основание применять нейросеть к такой
задаче: сравнение первого и последнего значения решает её без обучения.
100% на данном синтетическом test не означают 100% на произвольных
последовательностях. Это один фиксированный запуск, без оценки вариации по
нескольким seed. График train loss не обязан быть монотонным: mini-batch Adam
может временно увеличить loss; в CSV сохранены все реальные эпохи.

## Проверка корректности

Перед обучением все 89 аналитических производных BPTT проверяются центральной
конечной разностью с ε=10⁻⁶ на четырёх примерах. Проверяются исходные градиенты
до clipping. Максимальная абсолютная ошибка: 1.2305038×10⁻¹⁰,
максимальная относительная: 4.2432599×10⁻⁸. Проверка пройдена.

Из 1200 шагов оптимизации clipping применён на 25. Максимальная общая норма
градиента до clipping была 30.0505. Это наблюдение данного запуска,
а не утверждение, что любой RNN обязательно получит такую норму.

## Выходные файлы

Скрипты создают каталог `results/` при запуске. Готовые файлы результатов в репозиторий не включены; notebook содержит сохранённый вывод.

- `../results/metrics.json` — параметры, метрики, baseline, проверка градиентов.
- `../results/training_history.csv` — loss и accuracy train после каждой эпохи,
  включая эпоху 0 до первого обновления весов.
- `../results/gradient_check.csv` — все 89 сравнений производных.
- `../results/dataset.csv` — исходные значения, метки, ID пар и split.
- `../results/predictions.csv` — вероятности и предсказания после обучения.
- `../results/model_weights.npz` — финальные обученные веса.
- `../results/numerical_example.json` — три подробно посчитанных шага RNN.

## Численный пример на доске

Для `h_t = tanh(0.5*x_t + 0.8*h_(t−1))`, `h_0 = 0`, `x = [1, 0, −1]`:

| Шаг | Вход | 0.5x | 0.8h предыдущего | Сумма | h нового |
|---|---:|---:|---:|---:|---:|
| 1 | 1 | 0.5 | 0 | 0.5 | 0.4621171573 |
| 2 | 0 | 0 | 0.3696937258 | 0.3696937258 | 0.3537237885 |
| 3 | −1 | −0.5 | 0.2829790308 | −0.2170209692 | −0.2136768637 |

Здесь веса заданы вручную, а не получены обучением; это отдельная
одномерная иллюстрация, не веса обученной восьмимерной модели.

Для обратного порядка `[-1, 0, 1]` итоговое состояние равно `+0.2136768637`. Этот расчёт сохраняется в поле `reversed_example` файла `numerical_example.json`.
